# VLA 评测：从跑通到可靠比较 / VLA Evaluation

[项目索引](../README.md) · [个人主页](https://zsevene077-cyber.github.io) · [编辑方法](../CONTRIBUTING.md)

领域：模型评测、性能分析。记录年份：2026。

## 问题与参与 / Context and Contribution

具身模型的仿真评测既要等待推理，也要运行环境、保存结果和处理异常。我的关注点是：怎样缩短等待时间，同时保留清楚的实验条件和完整结果。

实习期间，我参与 LIBERO、RoboTwin2 等仿真环境的评测执行，跟进模型服务、评测 worker 和结果产出；对比评测并发与推理微批配置，记录耗时、显存、利用率和异常；检查 episode 唯一性、重复、缺失及补跑记录。

以下性能结果只对应一次 LIBERO 实验，不能将其移用到 RoboTwin2。

## 实验条件 / Experimental Conditions

| 条件 | 本次记录 |
| --- | --- |
| 时间 | 2026 年 7 月 |
| 模型与任务 | 训练后 DM0；LIBERO Spatial |
| 评测范围 | 10 个任务 × 50 episodes，共 500 episodes |
| 随机种子 | seed 7 |
| 推理服务硬件 | 单张 RTX 4090D |
| 基线配置 | 2 个评测 worker；推理无微批 |
| 对比配置 | 10 个评测 worker；batch 4；等待 20 ms |
| 时间口径 | 该次实验记录的 wall time |

这次配置同时改变了评测 worker 数和推理微批设置，因此观察到的是组合配置的差异，无法单独归因给其中一项。公开摘要没有列出完整评测端资源配置、模型权重版本和环境版本，不能据此认定两组总算力相同。

## 结果 / Results

| 指标 | 基线 | 对比配置 |
| --- | --- | --- |
| 评测耗时 | 55.8 分钟 | 32.0 分钟 |
| 服务 GPU 平均利用率 | 50.6% | 77.1% |

按记录中的耗时计算，减少约 42.7%。这一结果说明指定负载下组合配置能减少评测等待；更高的服务 GPU 利用率只是同次实验的资源观察，不等同于整个评测系统的效率。

## 证据与边界 / Evidence and Limits

- 这是指定模型、环境与配置的单 seed 性能结果，未在这里报告多 seed 重复实验或统计置信区间。
- 耗时减少不代表模型成功率提升，也不是所有模型、任务和硬件的通用加速比。
- 提高并发需要一起检查评测端内存、显存及异常情况。仅凭上述结果不能确定资源成本最优配置。
- 公开内容为历史实验摘要，原始运行日志和完整配置不随本仓库提供。

## 认识与下一步 / Reflection and Next Steps

我逐渐把“运行完成”理解成一组可核对的条件：进程结束、结果落盘、覆盖完整、错误解释清楚，再讨论性能。

后续可验证的想法是：在固定模型版本、样本清单与硬件资源后，分别改变 worker 数或微批配置，并重复运行，比较吞吐、内存与长尾耗时。此处是实验方向，尚未作为已完成结果。
