[项目索引](../README.md) · [个人主页](https://zsevene077-cyber.github.io) · [编辑方法](../CONTRIBUTING.md)

领域：机器人数据、系统工程。记录年份：2026。

## 问题与参与 / Context and Contribution

多相机录制结束后，转码、队列调度与文件核对仍会影响数据可用性。我参与多相机录制、机械臂状态读取、后台任务队列及转码流程的开发与排查，关注持续写入、暂停恢复、时间戳和派生文件的一致性。

这里分开记录两个实验：同一批既有录制的离线转码对比，以及真实相机配合静止机械臂的只读采集检查。两者回答的问题不同。

## 离线转码对比 / Offline Transcoding Comparison

| 条件 | 本次记录 |
| --- | --- |
| 运行环境 | Windows 后台视频任务队列 |
| 输入 | 同两条封存录制，共 3,090 帧 |
| 对比变量 | 4 路与 8 路并行转码 |
| 完整性检查 | 输出 MP4 哈希、时间戳载荷、原始数据哈希 |
| 设备运动 | 不包含物理机械臂运动 |

| 指标 | 4 路并行 | 8 路并行 |
| --- | --- | --- |
| 转码耗时 | 63.517 秒 | 41.265 秒 |
| 采样到的内存峰值 | 约 225.3 MiB | 约 448.6 MiB |

转码等待时间减少约 35.03%。8 个输出 MP4 与基线逐字节一致，时间戳载荷一致，原始数据哈希未改变。并行数增加同时带来了更高的内存峰值，因此加速与资源占用需要一起看。

上述内存数值是该次记录的采样峰值，不是所有运行的上界。公开摘要未列出完整 CPU、编码器参数和软件版本，不能将该结果推广为其他机器的固定加速比。

## 静止设备读取检查 / Static-Device Read Test

使用 4 路真实相机和两台静止机械臂，只读取位置状态；没有使能、归零、跟随或目标动作命令。测试完成 14 条录制，累计录制约 30 分钟。

| 检查项 | 记录结果 |
| --- | --- |
| 完成录制 | 14 / 14 条 |
| 派生 MP4 | 148 个 |
| 输出帧数 | 176,557 帧 |
| 解码核对 | 148 个文件，共 176,557 帧 |

这次检查支持该范围内的采集、后台处理及保存结果能够相互核对。后台进程与采集曾有时间重叠，但进程采样包含暂停时段，不能将其解释为 GPU 持续忙碌或持续满负载。

## 证据与边界 / Evidence and Limits

- 离线转码比较使用同两条输入，不是长期生产负载测试。
- 静止读取测试没有验证机械臂运动跟随、抓取或机械控制性能。
- 保存帧数和状态读取正常，不足以确认训练所需的视频与机器人状态时间对齐；这里不作对齐验收结论。
- 公开内容为实验摘要，原始采集数据、设备配置和完整日志不随本仓库提供。

## 认识与下一步 / Reflection and Next Steps

数据工程的优化需要同时回答两个问题：有没有更快，以及产出的数据是否仍然可信。

后续想法包括：增加不同长度录制的队列测试，检查中断恢复与资源峰值；另外设计专门的时间对齐验证，明确时钟、时间戳来源和误差判定。它们仍是待验证方向。
